# 税率与居民满意度验收

## 本步目标

让税收、供粮与居民满意度产生可见的经营取舍，保持范围可控。本步没有人口流失、移民、叛乱、军队士气、生产效率惩罚或消费升级。初始人口仍30，全部经济数值待平衡。

## 政策与顺序

| 档位 | 稳定ID | 每人基础税额 | 初始满意度50时税收 | 每日政策满意度变化 |
|---|---|---|---|---|
| 低税 | low | 0.6 | 15 | +2 |
| 标准 | standard | 0.8 | 20 | 0 |
| 高税 | high | 1.2 | 30 | -3 |

满意度初始50、范围0至100，税收基准除数60，沿用此前30×0.8×50/60=20的正常税收。税率在日结时按玩家最后选择的档位同时计算收入与政策满意度变化。切换不收税、不加满意度，也不能分别获取高税收入和低税好处。

每日日结顺序：粮食收获与居民实际消耗 → 材料入库 → 用变化前满意度计算税收 → 政策、供粮恢复、缺粮惩罚共同改变满意度 → 记录完成日期与账单。粮食仍先入库再消费，税收使用当日满意度变化前的值，惩罚与恢复影响后续税收。

    tax = round(人口 × 当前档位基础税额 × 日结前满意度 / 60)
    food_penalty = ceil(10 × 实际缺粮 / max(居民需求, 1))
    recovery = 1，当天无缺粮且日结前满意度 < 50，否则0
    after = clamp(before + policy_delta + recovery - food_penalty, 0, 100)

居民每天需粮15时，完全断粮扣10，缺2扣2。自然恢复不是额外发粮，也不在缺粮时生效。低税且低于50、正常供粮时会有+2政策和+1恢复，高税低于50正常供粮时会有-3政策与+1恢复；界面逐项说明。满意度达到边界时实际变化可能小于各项变化之和。

满意度0时税收0，但正常供粮仍允许自然恢复。金币上限10亿：tax_stored=min(tax, 上限-gold_before)，其余tax_overflow为明确损失，不让存档余额越界。没有金库玩法。

## 界面

管理面板显示满意度、下次日结采用的税率与按当前满意度估算的收入；当前档位按钮禁用以表示选中。低税/标准/高税按钮只发送政策命令，保存后可恢复。

最近一次政务账单单独显示采用档位、实际税收入库/上限损失、满意度前后值，以及政策、供粮恢复与缺粮各自的变化。历史采用档位可以与玩家目前为下一日选择的档位不同；当前预测也可能与上次实际税收不同。

例：低税首日50→52，税15；下一日高税按52征31，之后52→49。此时高税预测按49为29，上次实际账单仍31。不能因预测刷新而改写历史。

## 静态配置与动态存档

civic_settings.gd为Resource定义，game/data/economy/civic_settings.tres保存三档税额、满意度变化、上下限与恢复/缺粮参数；Godot原生.tres首行格式保留，其用途由此说明描述。civic_economy.gd统一预测、日结和账单校验，world_state.gd负责权威状态与结算连接，world_prototype.gd负责显示及政策命令。

快照v9新增根字段tax_policy、satisfaction、last_civic_ledger；SQLite结构仍v2，事务存档与滚动备份沿用原规则。v1至v8迁移时补标准税/满意度50/空政务历史，不改变库存、已收税、日期、建筑、退休记录或岗位，不追溯模拟历史饥荒。

新增字段示例，完整快照其余字段沿用前步：

```json
{
  "version": 9,
  "tax_policy": "high",
  "satisfaction": 49,
  "last_civic_ledger": {
    "day": 2, "policy": "high", "before": 52, "after": 49,
    "tax": 31, "policy_delta": -3, "recovery": 0,
    "shortage": 0, "food_penalty": 0, "delta": -3,
    "gold_before": 315, "tax_stored": 31, "tax_overflow": 0, "gold_after": 346
  }
}
```

载入校验政策白名单、满意度有限整数范围、账单日期、所有数值与公式、同日粮食缺口，以及账单满意度结果与世界当前满意度一致。历史金币不强制等于当前余额，允许该日结后发生合法建造和退款。读取后重新规范为整数，不保留JSON浮点表示差异。

静态平衡参数影响历史账单校验；后续修改公式或参数时必须升级存档并明确迁移历史账单，不能直接改配置后要求旧账单按新参数通过验证。空历史账单用于初始/迁移状态，完成下一次日结后生成。

## 后续边界

先观察三档政策与供粮反馈，再接入明确的人口增长/居民需求或军队招募。满意度不会在本步突然触发叛乱或删除玩家人口，下一阶段若加入这类结果应单独确定规则并验收。

实际窗口补充检查：初始面板显示满意度50/100、标准税、预计20，三档按钮均可识别；点击高税后下次预测变30，金币仍300、满意度仍50，未产生即时收益。临时画面检查未保存政策变更。
