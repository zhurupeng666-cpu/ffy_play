# 粮仓与粮食收支验收

## 本步实现

新增粮仓b_granary，3×3陆地建筑，费用木25/石10/金15，施工60份工作。基础公共储粮容量300，每座完工粮仓增加300，两名施工工人下约60战略秒完工。粮仓无生产岗位，不耗额外劳动力；施工继续使用全镇施工队。全部参数待平衡。

容量由已完工建筑的Resource静态food_capacity配置推导，不在存档重复保存当前容量。粮仓工地不增加容量，多座叠加。河道、占地、扣费和建造命令沿用现有规则。

## 日结与公式

保留此前先收获后消费的顺序，按三类生产来源统计整份粮食，生产信用不足一整份时跨日保留。新增公共容量对新收获生效：

    produced = farm + ranch + fishery
    stored = min(produced, max(0, capacity - opening))
    overflow = produced - stored
    needed = ceil(population * 0.5)
    consumed = min(needed, opening + stored)
    shortage = needed - consumed
    closing = opening + stored - consumed
    net = closing - opening

溢出粮食是明确损失，不保留在建筑中，也不在扩容后补发。消费腾出的空间在下一次日结可用于入库；因此日结后的库存可能为容量减15但当天仍有溢出，这是既定顺序的结果。居民、金币税收、工人岗位和生产速度均保持前步规则。

旧档已有的超容量粮食保留，不在读档或日结时截断。例如期初450、容量300，没有产量时正常消耗后435；若当日产41，新增41全部溢出，期末仍435。超容量期间给出提示，玩家可扩容或等待正常消耗。

其他资源尚无仓储限制；没有物流半径、建筑分仓、腐败、仓管工、粮仓升级、搬运成本或拆除减容。

## 界面

右侧显示当前储粮/容量；接近上限（剩余空间不超过15）或旧库存超过容量时显示提示。建粮仓按钮与住宅/农场同排，沿用占位美术。

最近一日摘要包含总产出、入库、溢出、消耗、净变化和税收。“展开粮食收支”显示来源拆分、期初期末、需求与缺粮。明细是历史账单，容量显示的是当日日结时的容量；在该日结后新完工粮仓不会改写历史。

仅保留最近一个结算日的明细，尚无历史图表或多日查询。收起/展开是纯界面状态，重开默认收起，操作不推进时钟、不改变存档数值。

## 数据与版本

战略快照v6新增last_food_ledger，初始或迁移后的无历史明细为{}。v1至v5均兼容读取：不虚构历史收支，不删除原有粮食，也不改变建筑/工人/生产信用；完成下一日后生成账单。SQLite表结构仍v2，继续事务保存与最近三份备份。

示例账单：

```json
{
  "day": 3,
  "opening": 295,
  "capacity": 300,
  "by_source": {"b_farm": 18, "b_ranch": 15, "b_fishery": 8},
  "produced": 41,
  "stored": 5,
  "overflow": 36,
  "needed": 15,
  "consumed": 15,
  "shortage": 0,
  "closing": 285,
  "net": -10
}
```

food_ledger.gd独立执行计算与完整校验，拒绝日期不符、缺字段、非法数值、不守恒或来源合计不符的账单；从JSON载入后恢复整数类型。账单closing不强制等于当前库存，允许该次日结之后发生合法库存变化，防止未来贸易等功能破坏历史账目。当前尚未接入贸易。

world_state.gd负责收获来源、容量派生、账单接入和迁移；world_prototype.gd只展示与发送建造命令。建筑静态配置使用Godot原生.tres格式，其文件用途由本说明描述；新增手写GDScript均包含中文文件及模块说明。
