# 人口与施工岗位验收

## 本步目标

把人口、空闲劳动力与已有施工队连接起来，通过工人按钮直接看到施工速度变化。全部初始数值均为待平衡参数。

## 模型与规则

- 总人口30 = 被抚养6 + 可就业24；可就业24 = 施工岗位0至2 + 空闲人口。
- 初始施工2、空闲22。岗位是全镇施工队的长期分配，所有工地按创建顺序共用同一队；无工地时不自动释放工人。
- 每名工人每战略秒贡献半份工作。使用整数labor_credit累计：每2个信用投入1份工作；余数0或1随存档持久化。0人不施工，1人半速，2人与前版工期相同。
- 住宅需要40份工作、农场80份；两人工期分别40/80战略秒，单人80/160秒。暂停冻结；倍速通过战略时钟作用，不另外乘施工速度。
- 初始住房30，每座完工住宅增加10。工地不计容量；住房容量由建筑推导，无冗余存档字段。
- 总人口仍固定30。容量增加不立即生成居民。此步不包含农场生产、移民、出生或人口损失。
- 调整岗位不扣钱、不创建或删除居民；拒绝负数、超过2和超过可就业人口的请求。

## 数据与边界

战略JSON快照升级v4，新增dependents、builders、labor_credit。SQLite表结构仍为v2，继续采用同一事务快照与滚动备份。静态建筑Resource配置不变。

读取v1至v3时补6名被抚养人口、2名施工工人、0工作余数，保持此前工期与施工进度；v4必须具备合法字段。拒绝小数、越界、缺字段和岗位超过可就业人口的坏档；读档失败不替换当前世界。

手动保存保留岗位和余数；退出不自动覆盖存档。全部测试使用隔离数据库，不改玩家进度。建筑当前仍不允许取消、退款或拆除。

## 自动与人工验收

labor_test覆盖人口守恒、分配边界、0/1/2人施工、战略暂停、住宅容量、半份工作跨数据库重开、v3迁移、新版非法字段、真实场景提示与读档恢复。此前施工队与日结测试继续执行。

Windows debug/release导出包分别通过独立进程写入1名工人和5.5份施工工作、读取后完成住宅，并验证容量为40。完整构建日志放在E:/playproject/builds/labor-build.log，未提交仓库。

人工可见反馈的步骤见开发测试指南“步骤九”。自动场景检查不替代用户对窗口布局与交互感受的验收。

## 后续顺序

下一步优先接入完工农场岗位、日结产粮和生产摘要，再逐步加入粮仓容量与加工链。人口增长与满意度在可验证生产闭环之后实现。

构建辅助修复：Windows PowerShell验收改用持有句柄的隐藏进程，避免快速退出时ExitCode丢失造成误报；保留20秒超时、独立日志和非零退出失败检查。
