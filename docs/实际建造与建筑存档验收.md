# 实际建造与建筑存档验收

## 本阶段行为

住宅和农场进入实际单次放置模式：选择建筑后，左键在合法且材料足够的位置确认，会扣费并生成真实实例，成功后自动退出建造模式。重复普通点击只选格，不连续建造；再次建造需重新选择建筑。失败保持模式，允许调整位置或取消。

费用均为待平衡参数：住宅2×2耗木20金10，农场4×4耗木25金10。确认时一次扣清所有费用，不允许部分扣费。此阶段立即落地，建筑显示ready状态；没有施工时间、岗位、生产或人口容量效果。

中央(6,6)开始的4×4区域现在是免费初始领主厅building_000001，替代原测试占用区。领主厅不可重复建造，不增加初始资源消耗。默认新世界建筑总数为1。

## 模块与状态

building_catalog.gd统一注册稳定定义ID，只接受b_hall、b_house、b_farm，禁止从存档指定任意资源路径。

construction_service.gd执行纯领域命令：校验命令ID → 检查成功回执 → 查定义 → 整块位置校验 → 全部费用检查 → 创建资源和实例副本 → 同步提交资源、实例、回执与下一ID。同步函数中途没有UI或异步回调。任何校验失败都不修改世界。

同一成功command_id和相同参数再次执行，只返回原building_id；同一ID用于不同位置或建筑会被拒绝。失败命令不写成功回执，可在条件恢复后重试。UI使用随机128位命令ID，每次进入建造模式生成一次，成功或取消后清除。

WorldState新增buildings、next_building_id和applied_commands。实例保存id、def_id、cell数组、level=1、state=ready。静态尺寸与费用仍在Resource，不复制进存档。下一实例ID递增且不复用；暂设256实例及编号上限保护。

TownMap只接收实例和资源副本，推导占用、可负担提示并绘制带名称的占位块。确认建造时服务重新检查权威世界，不依赖可能过时的绿色预览。读档后重建占用和画面，不因恢复显示再扣一次费。

## 存档版本与兼容

动态快照版本从1升为2；SQLite结构版本也升为2，但二者是独立概念。

v1快照载入时保留日期、资源、暂停和倍速，补入初始领主厅、next_building_id=2与空成功回执，迁移不扣材料。迁移在临时对象完成，不会自动覆盖原快照；用户点击保存后才写入v2。

v2载入检查建筑定义、实例ID、编号上限、等级状态、整块边界、相互重叠、唯一初始领主厅，以及回执对建筑和位置的引用。重复ID、未知定义、悬空回执、负库存或非法日期均拒绝，不替换当前世界。

SQLite world_snapshot表仍保存当前JSON快照；新增snapshot_backup表，在同一次保存事务中保留最近三个旧快照。写入失败时当前快照和备份一起回滚。尚未提供备份恢复按钮，不能把保留旧快照等同于完整的玩家恢复功能。旧版程序可能拒绝结构版本2，不支持降级读取。

存档路径仍是local_data/saves/world_prototype.db；旧金币测试档frontier_test.db不变。没有退出自动保存，建造后仍应点击保存战略进度。

## 已完成测试

- 正常住宅只扣木20金10，实例总数变2。
- 重叠、越界、不可建领主厅、材料不足均不改变资源、计数器或回执。
- 同一成功命令重放不扣费；同一ID更换参数被拒绝；读档后幂等仍有效。
- 实例计数器读档后连续递增，编号上限拒绝且不产生副作用。
- 材料不足预览变红，补足材料后恢复合法提示。
- v1迁移保留金币，首次写v2保留旧快照。
- 重开数据库后建筑、位置、费用与回执一致；坏建筑和悬空引用拒绝。
- 连续保存只保留三个旧快照；注入SQLite更新失败后当前快照和备份保持不变。
- 原SQL、场景、战略、地图与放置测试继续通过。
- debug和release均通过旧金币、战略日期及新建筑三组跨进程保存读取，共12次实际程序验收。
- 图形验收使用临时独立副本：住宅落地后木100、金290、建筑2座；关闭重开后读取恢复住宅名称与位置，再次重叠建造失败且资源不变。用户手动存档未被测试覆盖，临时副本已清理。

自动入口Godot: construction test，成功标记BUILD_PASS。构建脚本包含所有七项领域与界面回归，以及导出程序验收。
