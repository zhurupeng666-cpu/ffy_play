# 施工进度与完工状态验收

本阶段确认建造后生成constructing工地，立即扣费并占地，施工完成才变成ready。已入队工地暂不可取消、退款或拆除；右键、取消按钮和Esc只退出尚未确认的放置模式。完工尚不增加住房、岗位或产粮效果。

## 规则

当前一支抽象施工队按实例创建顺序逐座施工，每个战略秒投入一份工作，不并行。住宅需40战略秒、农场80战略秒，均为待平衡参数。4倍速下单独施工分别约10、20现实秒；排队时间另计。人口与劳动力消耗尚未接入。

暂停不推进；倍速和卡顿追赶复用固定步战略时钟。每步先推进施工再执行可能发生的日结。达到所需工作量即标记ready，此后不重复施工或扣费。当前工地显示百分比，等候工地保持0%；侧栏显示完工数、待完工数、当前施工与等待数量。

## 数据与兼容

BuildingDefinition新增build_work。确认时将其固化到实例work_required，work_done从0开始，避免以后修改静态工期改变已保存任务。

世界快照版本升为3，SQLite结构版本仍为2。v1沿用原迁移并补已完工领主厅；v2已有建筑保持ready，迁移为work_required=0、work_done=0，不会重新施工或扣费。v3保存每座工地的状态与进度，并检查非负、上限、进度和状态一致；领主厅必须已完工且工期0。读档按稳定实例ID恢复创建顺序，防止存档数组排序改变队列。

原来的幂等回执、资源、日期、倍速、暂停和备份规则继续保留。施工进度不会退出时自动保存，仍需手动保存战略进度。

## 验收

暂停时不施工；10战略秒住宅25%、农场等待0%；保存关闭重开恢复25%；4倍速再推进7.5现实秒住宅恰好完工，农场从下一逻辑秒开工；再20现实秒农场完工。跨日税收与粮耗正常，施工不再次扣材料。重复成功命令不使完工建筑重新开工。

负进度、超上限进度、满进度却标记施工中等坏档被拒绝。界面回归通过实际放置、25%显示及存档恢复后的地图数据同步。所有八项回归通过，debug/release均通过实际导出进程的中途保存、重开读取和继续完工验证。最终实际图形观感交由本步骤手动测试确认，不将无窗口回归等同于人工试玩。

## 原生库配置

本机多个Godot进程发生SQLite临时热重载DLL争用，故将gdsqlite.gdextension设置reloadable=false。只关闭原生库热替换，不影响GDScript编辑，也未改原生DLL或许可证。已有~开头运行时DLL留在本机并忽略，不提交、不删除他方正在使用的文件。
