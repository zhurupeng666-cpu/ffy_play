# 取消训练与部队解散验收

## 用户确定的规则

训练取消按未完成比例退金币与木材、向下取整；现役解散不退款。退款使用本批次招募时的实付费用，未来调价不追改旧批次成本。例：每批50金币/5木材、训练60秒，30秒时取消退25金币/2木材，1秒时取消退49金币/4木材。

取消或解散后，整批5人立即从军职释放为空闲，城镇总人口不变，军营编额和在训限制同时释放。新招募使用新批次ID并重新扣费。所有数值仍待平衡。

## 已发生军需的保留

已付的历史军需不退；仍在批次上的ration_credit/wage_credit转入retired_army_cost公共待结账户。退役后不再累加新服务信用，公共账户每日日结兑付整数部分并保留零头。多个退役批次的零头可以合并。不会因解散、读取旧进度或拆军营抹掉已经发生的开销。

例：5人训练30秒，两种信用各150，相当于1.25军粮/金币；取消后下次日结仍各结算1，剩余30信用即0.25继续保留。没有军队也显示待结信息，已有费用与新服役费用区分。实际不足仍沿用上步规则：实付不超过库存，缺额只记本日账单，不形成累计债务。

为证明不丢费用，保存累计已结应付单位：

    所有退役批次原始ration_credit合计
      = 当前待结ration_credit + ration_settled × 120
    工资信用采用相同关系

settled表示已进入日结的应付整数，而非保证已实付；实际支付和缺额保存在军事日结账单。这些总量在每次载入时重算校验。不是让退役批次继续产生费用，也不改变基础口粮每日15的算法。

## 界面与确认

选中军营后，活动批次列表显示稳定编号、人数、训练/现役。切换军营只操作对应批次；在训显示取消这批训练，现役显示解散这批部队。列表只在批次身份或状态变化时重建，保留同军营内稳定选择。

确认框列出目标与人数、返回劳动力、退款和退款上限损失、该批次未结军需。打开时冻结世界，关闭或执行后还原此前的暂停/运行状态。预览捕获世界快照签名，执行前世界改变则拒绝，需重新确认；保留部队不改变资源、人数、信用或进度。

全部清空后军营可以拆除。退役批次只作历史，不出现在当前列表，不占编额或人口；历史可引用已经拆除的军营。当前没有逐人裁减、退役后召回、训练恢复、补员、军团或战斗。

## v11数据与兼容

- 活动troops增加paid_cost，规范保存wood/stone/gold实付费用。
- retired_troops保存取消或解散前完整批次快照，包括当时状态、进度、费用与未结信用。
- disband_commands保存成功回执，字段troop_id、tick、refund和overflow。
- retired_army_cost保存ration_credit、wage_credit、ration_settled、wage_settled。

例：

```json
{
  "version": 11,
  "retired_army_cost": {"ration_credit": 150, "wage_credit": 150, "ration_settled": 0, "wage_settled": 0},
  "disband_commands": {
    "cancel-first": {"troop_id": "troop_000001", "tick": 150, "refund": {"wood": 2, "gold": 25}, "overflow": {"wood": 0, "gold": 0}}
  }
}
```

完整快照还包含既有世界字段及完整退役批次，以上仅展示新增字段。原recruit_commands必须能唯一引用活动或退役批次；同一招募命令不会复活历史部队，同一退役命令不会重复退款或再转移开销。不同命令再次请求已退役目标拒绝；部队ID不复用。

恢复时校验所有活动/退役ID与计数器、兵种来源/人数/进度、军营引用（退役允许引用历史军营）、仅活动部队占编额与劳动力、每批次唯一招募回执、每退役批次唯一退役回执、实付成本与按比例退款、日期和公共军需守恒。退役军营本身仍由原建筑历史校验保护。

v10活动部队补冻结的实付招募费用金币50/木材5，原进度、服务信用、人口与资源保留，不产生退款或历史追缴；v1至v9仍默认无军队。新快照v11，SQLite结构仍v2，事务存档与滚动备份保持。

当前最多64活动批次、512累计批次。累计达到512拒绝新招募，旧部队仍能全部退役；不自动删除命令证据。以后需要长局历史压缩时另做明确版本迁移。

## 模块与验收

army_disband_service.gd负责预览、退款、原子退役和历史恢复；army_service.gd只对活动部队推进训练及新开销，对公共退役账户按整数日结，恢复时合并校验活动与历史。world_state.gd保存新字段；world_prototype.gd协调军营批次列表、确认框与待结显示。所有手写新增代码有中文用途及模块说明。

army_disband_test覆盖：半程与向下取整退款、重复/冲突/失效请求、旧招募不复活、ID递增与重新征募、立即返还兵源、跨连接恢复活动及退役历史、多个零头合并、日结一次、退役无新增开销、现役零退款、空营可拆且历史可载入、退款上限、坏历史/费用/重复ID/未结守恒拒绝、v10迁移、确认冻结/取消无副作用/过期拦截及真实军营界面同步。
