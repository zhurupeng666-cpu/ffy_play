# 自由人数军团编制验收（步骤十八）

本步按用户选择，允许拆分招募批次，按人数自由编入军团。军团是现役士兵的组织关系，尚不具备移动、战斗或出征能力。所有容量与经济数值均为待平衡参数。

## 规则与边界

- 只可编入现役部队，不能编入训练或退役批次。原招募仍是每批5人，军团按1人调整，不拆改原招募、费用和训练记录。
- 同一批5人可分配为甲团2人、乙团3人；各团分配合计不得超过原批次人数。一团可组合多个批次。
- 数字框表示“本团从所选批次编入的总人数”，不是追加数量；重复保存相同数字不会重复增加。设置0或点移出本团会释放编制配额。
- 一团最多20人，同时最多8个活动军团，累计最多512个军团（含撤销历史）。新建空编制免费。达到历史上限后拒绝新建，不删除防重记录。
- 编入、移出、撤销军团均不改变总人口、空闲劳动力、现役人数、原军营编额或库存；也不会叠加军粮军饷。未编入军团的现役士兵仍占兵源并接受维护。
- 撤销军团时暂停并确认，士兵回到未编入状态，继续现役。需要归还劳动力，应回到军营解散对应原始批次；该操作仍按整批5人执行，不支持逐人退役。
- 解散原始部队时，从所有军团同步移除其成员引用，避免一处解散后另一处仍有虚假士兵；剩余空军团保留。
- 暂无自定义军团名、逐人装备、战损补员、军团移动、补给线、战斗、驻防转移。当前成员引用原军营现役池，将来移动时须先补充驻地、归属与补给模型。

## 界面与手动验收

入口：E:\playproject\builds\FrontierGuardian\release\FrontierGuardian.exe。退出旧程序后打开新版，可读取已有存档。右侧面板向下滚动找到“军团管理”，点击展开。

1. 军营至少有一批训练完成的5名步兵。没有时建军营并招募，等训练结束。先暂停，记录现役人数、空闲劳动力与资源。
2. 点“新建军团”，选择现役批次，人数设为2，点“保存本团人数”。第一团应显示2人。
3. 再新建第二团，选择同一批次，设为3并保存。第二团3人，同批次未编入0。第一团仍2人，原始现役仍5人，空闲与资源不变。
4. 该批次全部编完时，第二团最多3人。先在第一团改为1，再回第二团改为4，应成功。不要把数字误当作追加人数。
5. 在第二团点“移出本团”，应释放4人配额，不返劳动力、不退款。之后可再次编入。
6. 撤销第一团时，先点“保留军团”，组织和资源不变；重新打开确认撤销，军团消失，但士兵继续现役且照常维护。
7. 保存、退出重开并读取，军团、人数和未编配额正确恢复。读旧v11存档时应保留原部队，只是没有军团。
8. 可另用测试进度确认：一批士兵分配到多个军团后，回军营解散该原始批次，各团对应人数同步消失，空闲仅增加该批人数一次，现役不退款。

通过标准：5人可自由拆为2和3，不能跨团超配；无重复兵源和军需；移出/撤销保留现役；真实退役同步清理成员；跨进程存读档结果一致。测试前若要保留原进度，先不要保存临时调整。

## 经济口径

军团只是编组视图。每日维护仍由原始部队的实际服役时间累计：每人每日额外军粮1、军饷1，训练和现役均计入，整数日结与余数规则沿用步骤十六、十七。两团2+3人的预算显示合计5，已经包含在全军维护内，不再次收费。居民基础口粮仍按总人口计算。

## 配置与存档

静态配置：game/scripts/legion_settings.gd声明Resource字段，game/data/military/legion_settings.tres提供20人、8活动、512历史上限。原生tres/uid文件保持引擎格式；用途由本说明记录，不写入非法注释。手写脚本均包含中文文件说明和函数职责注释。

动态战略快照升级v12，SQLite结构版本仍v2：军团随原战略快照一起事务保存，不另设第二套库存。新增根字段示例（其余原字段省略，不是可独立读取的完整存档）：

```json
{
  "version": 12,
  "legions": [
    {"id": "legion_000001", "name": "第1军团", "state": "active", "members": [{"troop_id": "troop_000001", "count": 2}]},
    {"id": "legion_000002", "name": "第2军团", "state": "active", "members": [{"troop_id": "troop_000001", "count": 3}]}
  ],
  "legion_create_commands": {"example-create-a": "legion_000001", "example-create-b": "legion_000002"},
  "next_legion_id": 3
}
```

撤销后保留同一ID、state=closed且members为空。ID不复用，创建命令回执不删除，重放旧创建不会复活军团。人数命令设置绝对值，天然避免重复累加；撤销重复执行无额外效果。确认撤销时以完整世界快照校验，状态变化则拒绝过期确认。

读取时校验成员正整数、同团批次唯一、现役引用、跨团人数总量、军团容量、身份和创建回执；不接受训练成员、悬空引用、关闭军团残留成员、负数或小数人数。v1至v11旧档默认空军团，不追收费用。将来降低Resource容量可能使旧存档无法通过校验，应伴随明确的版本迁移，不能直接改配置上线。
