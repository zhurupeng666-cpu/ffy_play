# 开发测试指南

本文提供每个已完成步骤的手动测试入口与明确预期。后续增加新功能时同步追加测试方法。

## 步骤一 开发环境与最小工程

### 运行与暂停

1. 用VS Code打开 E:\playproject\ffy_play\FrontierGuardian.code-workspace。
2. 按F5，选择 Frontier Guardian: Debug（如要求选择）。
3. 看到Frontier Guardian测试窗口，Running后的秒数持续增加。
4. 等待3秒后按空格：应显示Paused，秒数停止。
5. 再等待3秒：数字应保持不变。
6. 再按空格：应恢复Running，秒数继续增加。
7. 按Esc：游戏窗口关闭。

通过标准：窗口可显示，计时可推进，暂停不计时，恢复后继续计时，退出正常。若窗口显示后像卡住，先检查VS Code是否还留有断点；Shift+F5可停止调试。

### 断点和变量

打开game/scripts/main.gd，在 elapsed_seconds += delta 行左侧单击设置红色断点（当前第21行），按F5。应看到代码行变黄，左侧Locals可展开查看delta；在Members中可查看场景成员。再次单击红点取消断点，再按F5继续；Shift+F5停止。

已实际验收：断点命中_process，第21行高亮；Locals显示delta=0.03162。该数值随帧时间变化，不要求复测时相等。

### 补全连接

右下角Godot Tools状态应为Connected。如为Disconnected，按Ctrl+Shift+P，执行 Godot Tools: Start the GDScript Language Server for this workspace。端口为6008。曾出现的找不到game/godot路径问题，已通过工作区级引擎路径配置修复；已确认状态Connected。

可在脚本中尝试Ctrl+Space查看建议，不保存临时测试修改。已有的本地语言服务协议测试返回有效补全数据；补全弹窗未作为本次最终验收依据。

### 自动测试

从VS Code菜单“终端 → 运行任务”选择 Godot: smoke test。末尾应显示 SMOKE_PASS: scene, time, pause, resume，退出码为0。此测试不需要图形窗口。

## 文件用途索引

- FrontierGuardian.code-workspace：打开game工作目录并设置本机引擎与语言服务路径。
- game/project.godot：引擎工程入口、启动场景、Compatibility渲染和开发日志位置。
- game/scenes/main.tscn：占位测试界面的节点布局。
- game/scripts/main.gd：场景计时、暂停和键盘事件。
- game/tests/smoke_test.gd：自动检查运行、暂停和恢复。
- game/.vscode/settings.json：单独打开game时使用的编辑器设置。
- game/.vscode/launch.json：F5调试入口。
- game/.vscode/tasks.json：自动测试入口。
- game/.vscode/extensions.json：推荐安装的开发插件。
- .uid文件：Godot自动生成的资源标识，不手工添加注释。

严格JSON文件保持合法格式，采用本索引说明用途；GDScript文件使用中文文件头与函数或模块注释。

## 步骤二 SQLite保存与重开读取

1. 打开FrontierGuardian.code-workspace，若仍有旧游戏在运行，先按Shift+F5停止，再按F5启动新场景。
2. 看见“测试金币：100”与“数据库就绪”。
3. 点击“金币 +10”三次，应变成130，提示“尚未保存”。
4. 点击“保存”，应显示“保存成功：130金币”。
5. 按Esc关闭，再按F5重新启动，初始应恢复100。
6. 点击“读取”，应恢复130，并显示“读取成功”。
7. 再加一次变成140，但不保存，直接关闭；重开后读取仍应为130。

通过标准：保存的数据能跨进程保留，未保存的修改不会覆盖旧档。首次未保存时直接读取，应该提示“暂无存档，请先保存”。当前只有一个手动测试槽，新保存会替换这个测试槽。

开发数据库位置：E:\playproject\ffy_play\game\local_data\saves\frontier_test.db。无需安装MySQL、启动服务器或手工建表。数据库与日志不提交Git。

自动测试：运行任务 Godot: SQLite test。预期输出 SQLITE_CHILD_REOPEN_PASS 和 SQLITE_PASS，退出码0。运行任务 Godot: all tests 可顺序执行SQLite与场景回归。

断点测试请按代码内容定位 elapsed_seconds += delta，不再依赖旧行号；新增存档模块后文件行号已变化。

下一步：准备同版本导出模板，验证Windows独立程序加载SQLite与保存读取，再进入正式经营数据与战略时钟。

## 步骤四 战略时钟与资源面板

通过标准：倍速有效，午夜只结算一次，暂停不推进，战略存档能恢复后继续正确结算。超过第2日再暂停时，每多过一天应再扣15粮、加20金；请按实际日期核对。

自动测试任务：Godot: strategic test、Godot: world UI test；Godot: all tests包含全部领域和场景回归。构建流程还检查debug/release的独立进程快照保存读取。

下一步：等距城镇格网、镜头操作和格子选择，为建筑占地预览准备基础。正式地形与建筑视觉在确定样式后再制作。

## 步骤五 等距城镇格网与镜头

1. 重新打开独立release程序，或在VS Code按F5。左侧应出现菱形格网，右侧保留战略面板。
2. 鼠标移动到地图格上：出现黄色边线，下方悬停坐标跟随变化。
3. 左键点击一个格：出现绿色选择标记，下方选中坐标固定。
4. 按住鼠标中键拖动：地图移动，右侧面板不动；松开后不再拖动。
5. 在地图上滚动滚轮：地图缩放，所指地块仍对应同一坐标，已选择的格不变。
6. 按Home或点击镜头复位：地图回中，缩放回75%，选择仍保留。
7. 在地图上点右键：选中坐标变成短横线。
8. 保持战略暂停做上述操作，人口、粮食和金币应完全不变；原4倍速日结与战略存档仍可照步骤四复测。

通过标准：点哪里选哪里，移动缩放后坐标不偏，地图不会盖住管理面板，地图操作不扣资源。缩放范围50%至200%。初始图幅可能裁剪边缘，可缩小或拖动查看全图。

镜头和选择暂不保存，重开复位属于预期；已有战略档不受影响。还没有建筑，点击选格不会放置建筑。

下一步：建筑占地预览与越界、重叠合法性检查，再接入实际建造扣费。

## 步骤七 实际建造与建筑存档

注意：本步骤取代步骤六的“左键仅预览”。当前左键会真正建造并扣材料；成功后自动退出单次放置模式。

1. 重开独立release程序，保持暂停，先不要读取旧档。初始木材120、金币300，中央为领主厅，建筑数1。
2. 点击建住宅2×2，在绿色空地左键确认。应留下带住宅名称的占位块，木材变100、金币290，建筑数2。
3. 再次选择建住宅，点击已建住宅或领主厅占地：应变红并提示建造失败，木材和金币不再减少。
4. 农场仍为4×4，成功费用木25金10；越界和材料不足不能建造也不能扣费。材料不足时预览会显示具体短缺。

通过标准：成功一次只扣一次，失败不扣，保存重开恢复建筑而不再收费。若测试前读取了旧进度，以当时资源为基准核对扣减量，不要求余额恰好100和290。

旧战略档可直接读取，新版会补初始领主厅而不扣材料；不用删除旧档。建造不会自动保存。新建筑本阶段即时落地，尚不增加人口容量或产粮。

自动测试任务Godot: construction test，预期BUILD_PASS。all tests和Windows构建已加入建筑规则与存档回归。

## 步骤八 施工与中途存档

当前替代步骤七的即时落地：确认后先是工地，费用仍只扣一次。

1. 重开程序，保持暂停，建一座住宅。应出现0%工地、待完工1座，木100、金290。
2. 选择4倍速并继续，约5秒后暂停，应看到接近50%的进度。保持暂停等待3秒，百分比不变。
3. 点击保存战略进度，退出重开后读取，百分比、日期、资源和暂停状态应恢复，不重新扣费。
4. 继续4倍速，剩余约5秒完成。建筑名称不再带施工百分比，完工数增加、待完工数减少。
5. 可选：先住宅后农场同时下单，住宅先施工，农场0%等待，住宅完成后农场才开始。

通过标准：有进度、能暂停、排队正确、中途存档能继续，完工不重复扣费。工期为待平衡参数；旧档中的已完工建筑保持完工，不必重建。完成后暂不产粮或增加人口容量。

自动任务Godot: work test，预期WORK_PASS；all tests和Windows构建已包含该回归。已确认的工地本阶段不能取消或退款。

## 步骤九 人口、住房与施工岗位

本步骤替代此前“住宅没有人口效果”的说明：完工住宅提供10住房容量，人口仍固定30人，不自动增加居民。

1. 退出旧程序，再打开 release/FrontierGuardian.exe。先不读档：应显示人口30 / 住房30，可就业24、被抚养6、施工2、空闲22。右侧可滚动。
2. 保持暂停，建一座住宅。点两次“工人 -1”：施工0、空闲24，提示已停工。选择4倍速并继续，等约3秒；日期推进而工地仍为0%。
3. 暂停，点一次“工人 +1”，变为施工1、空闲23。继续4倍速约5秒后暂停，工地约25%，说明单人工期变慢。
4. 点击保存战略进度，退出重开并读取。应恢复施工1、空闲23、同样的百分比和暂停状态；资源不再次扣费。
5. 点一次“工人 +1”，变为施工2、空闲22。继续4倍速，剩余约7至8秒完成住宅；住房从30变40，人口仍为30。
6. 多点加减按钮：人数不能小于0或大于2，不影响人口和金币。工地完工后岗位仍保留，可手动释放为空闲。

通过标准：0人停工但时间继续，1人半速，2人原速；人口账守恒，完工才加住房，岗位和中途进度重开可恢复。以上时长和人数都是待平衡参数，鼠标操作及取整会产生少许进度误差。

自动任务Godot: labor test，预期LABOR_PASS。all tests与Windows构建已加入劳动力测试；实际debug/release独立进程验收会保存1名工人和半份工作余数后读取续建。个人存档不被测试覆盖，仍需手动保存。

范围边界：本阶段没有出生、移民、失业惩罚、人口增长、农场岗位或粮食生产；原有日结规则保持不变。旧v1/v2/v3存档读取时默认6名被抚养人口和2名施工工人，保留建筑与原有进度。

## 步骤十 农场、牧场、沿水渔场与日结产粮

本步骤替代此前“没有粮食生产”的说明。三类建筑统一产粮，工人默认0，需要完工后手动分配。日结先收粮再消耗，工作不足一天按实际时间累计。

1. 退出旧程序，打开release/FrontierGuardian.exe。暂不读取旧档。右侧上方可看到日期、粮食180、暂停/速度和存档按钮；下方建筑、岗位区域可用滚轮上下查看。
2. 保持暂停，分别建农场4×4与牧场4×4。两者应落地为工地，水域不能建造。可在坐标(2,4)、(10,10)附近找空地。
3. 选择渔场3×2：内陆为红色并提示必须沿水；占地压到蓝色河道也变红。沿北侧蓝色河道的岸上陆地为绿色，例如锚点(2,1)，左键确认。绿色才可建造，失败不能扣钱。
4. 保持施工工人2，4倍速继续约55秒，三座建筑依次完工；尚未安排生产时粮食只有居民日耗，没有建筑产量。暂停。
5. 向下滚动右侧面板，在下拉框分别选择农场、牧场、渔场，使用“生产工人 +1”分配3、3、2人。应显示生产岗位8、施工2、空闲14，三类全天折算产量18、15、8。再次加人会被岗位上限拒绝，不扣人口或金币。
6. 继续到日结：首次按当天实际在岗时间发放，可能不足41。再经历完整一日，账单应显示产粮+41、消耗-15，粮食净增加26；4倍速完整一日约30秒。
7. 在一天中途暂停并保存，退出重开后读取。三类位置、完工状态、生产工人数、所选建筑累计粮食和库存应恢复。继续到日结后产量不丢失、不重复发放。
8. 可选：把某建筑工人减为0，已有累计粮食保留，新时间不再累计；恢复工人后继续。暂停时所有生产停止，切换倍速不改变完整一天的产量。

通过标准：农、牧、渔均可建造和工作；渔场必须沿水，不能建在水上；岗位共用人口；每日正确产粮消费；进度和岗位能随存档恢复。数值均待平衡。

旧档直接读取即可，原有农场默认0生产工人，不补发历史粮食。固定河道为y=0；旧档若已有建筑占用该行，保留原建筑，不拆除或移动，新建建筑不再允许占河道。

自动任务Godot: food test，预期FOOD_PASS。完整构建包含10项测试，debug/release分别执行SQLite、战略、施工和农牧渔的独立进程写入/读取验收。测试库与个人存档隔离。

## 步骤十一 粮仓容量与粮食收支明细

本步骤将此前10亿安全上限替换为实际粮食仓储容量；其他资源暂不限制仓储。数值全部待平衡。

## 步骤十二 森林、石矿与建设材料生产

本步加入固定森林和石矿资源点，伐木场/采石场必须正交紧邻对应资源，不能直接盖在资源格上。当前资源点持续供给，不枯竭，参数全部待平衡。

1. 退出旧程序并打开release/FrontierGuardian.exe。可读取原进度；森林显示为绿色“林”格，位于x=0、y=11至13，石矿显示灰白“矿”格，位于x=15、y=4至6。右侧面板可滚动查看新建造按钮。
2. 选择伐木场3×3，先移到普通内陆空地：应变红提示须紧邻森林。移到资源格上也应被拒绝。紧邻森林的空地，例如锚点(1,10)，应可建造。
3. 伐木场为基础营地，只花金币10、不耗木材，避免已有木材耗尽后无法恢复生产。确认后不重复扣费，工地仍需施工。
4. 选择采石场3×3，森林附近不能替代石矿；在石矿旁空地，例如锚点(12,4)，确认建造，费用木25、金15、不耗石材。
5. 保持施工2人，4倍速继续，两座依次完工约35秒。完工不自动安排生产；此时材料不因建筑存在就增加。
6. 在生产下拉框中分别选择伐木场、采石场，各安排3人。应显示生产岗位6、施工2、空闲16；维持完整一日应产木24、石15。若原有农牧渔工人，空闲人数需额外扣除它们。
7. 继续到日结，材料摘要应显示入库量，木材/石材库存增加。首次不足一天按实际工作时间计算，第二个完整工作日再核对+24/+15；4倍速完整一日约30秒。
8. 一天中途暂停、保存，退出重开读取。新建筑位置、岗位、木石库存、累计产量和上次材料日结应恢复。减为0人后停止新积累，已做工作保留；暂停时不产出。

通过标准：林矿类型匹配、必须紧邻且不能覆盖；只有完工并有人时生产；材料与粮食不混算；岗位守恒；中途读档能续产，日结不重复发放。

旧建筑即使刚好位于新增资源点也会保留原址，避免破坏已有存档；新建筑遵循资源格限制。资源点目前不枯竭、无半径效率差异、无搬运/工具消耗；木石只有10亿数值安全上限，尚未接入材料仓库。

## 步骤十三 点击建筑查看详情与直接管理岗位

3. 在详情点击“本建筑工人 -1/+1”，只应改变当前选中建筑；原下拉框也应选中同一建筑。零人时减号禁用、满员或没有空闲人口时加号禁用。原生产下拉框仍可用，切换后地图高亮与详情同步。

通过标准：建筑整个占地都可点选，选中、下拉框和岗位目标一致；进度持续刷新；非生产建筑没有误导性的岗位操作；只读查看无资源变化；读档后不会误改旧对象。

若尚无完工生产建筑，可先建伐木场：合法临林位置(1,10)，2名施工工人、4倍速约15秒完工后即可测试岗位。切换生产下拉框时会退出尚未确认的建造预览，避免同时保留两个操作目标。

详情右侧会自动滚动到可见位置；暂停/倍速和保存仍在该面板上方，可滚动返回或用空格暂停。建筑选择属于界面状态，不随战略存档恢复。暂无升级、拆除、取消工地或单座停产开关，停产可把该建筑工人减至0。

## 步骤十四 取消施工与拆除建筑

本步骤替代此前不能取消/拆除的限制。退款规则由用户确定：工地按未完工比例退木石、向下取整，不退金币；完工拆除不退款。所有原型数值仍待平衡。

1. 退出旧程序，打开release/FrontierGuardian.exe。为核对具体余额可先不读档，保持暂停，建一座住宅：木材100、金币290、工地0%。
2. 新工地详情中点击“取消施工”。确认框应显示退木20、石0、金币不退；时间暂停。先点“保留建筑”，工地与资源都不变，时间恢复打开窗口前的状态。
3. 再次点击取消施工并“确认执行”：工地消失、占地释放，木材回120、金币仍290。可在同一位置重新建造，成功后正常扣费，不会复用旧实例ID。
4. 可选比例测试：重新建住宅，施工2人、4倍速约5秒后暂停，接近50%时再取消。确认框显示的退款应约木10，按实际已完成整数工作量向下取整；不是全额退款。
5. 完工建筑详情显示“拆除建筑”。确认框会说明释放工人、待入库产量损失、住房和储粮容量变化。完工拆除不退木、石或金币；领主厅没有拆除入口且不能移除。
6. 拆除生产建筑应立即释放它的生产工人，并停止后续产量；该建筑未入库的粮食/材料包括零头会丢失。拆除粮仓只降低容量，现有粮食保留；超容量期间不能接收新粮。
7. 保存，退出重开并读取。已移除建筑不能重新出现，占地可继续使用；原址重建的建筑应保留。若删除的是当前施工工地，排队中的下一座从自己的进度继续。

通过标准：取消确认没有副作用，确认后退款/释放占地准确，完工拆除不退款；重复点击或重开不重复返还；领主厅受保护；旧档正常读取。

确认窗口期间时间冻结，关闭或确认后恢复原暂停/运行状态。影响预览过期时操作会被拒绝，需重新查看确认。不会自动保存，执行后仍需手动保存。

退款公式：floor(实付材料 × (所需工作 - 已完成整数工作) / 所需工作)。未满一份的施工信用不计已完成整数工作；取消当前工地时这部分信用清空，不转给后续工地。金币从不退。退款达到10亿安全上限时，超出部分明确列为损失。

当前最多保留2048条移除历史；达到上限时拒绝新的取消/拆除，不擅自清理防重复记录。14项自动测试及debug/release共32项独立进程验收已纳入完整构建。自动任务Godot: removal test，预期REMOVAL_PASS。

## 步骤十五 税率与居民满意度

本步替代此前固定每日收税20和缺粮仅提示的规则。新世界默认标准税、满意度50；供粮充足且维持标准税时仍每日20金币，兼容原先正常经营的基准。所有参数待平衡。

1. 退出旧程序，再打开release/FrontierGuardian.exe。若要核对以下准确余额，暂不读档、也不要建造。应显示满意度50/100、下次日结标准、预计税收20。
2. 点击低税：预计税收变15，金币仍300、满意度仍50。反复切换不能立即加钱或恢复满意度。
3. 选择低税，4倍速继续，到第2日后暂停（完整一天约30秒）。应为金币315、满意度52；上次政务账单显示低税、税收入库15、满意度50→52。
4. 改高税，再运行完整一天，到第3日暂停。以52满意度计算本日税31，应为金币346、满意度49。当前预计税收会随49满意度变为29，上次实际账单仍显示31，二者不是同一时点。
5. 点击低税但不继续，满意度不应立即恢复。正常供粮且满意度低于50时，下次低税日结包含政策+2与供粮恢复+1；高于或等于50时没有这项自然恢复。
6. 保存，退出重开并读取。所选税率、满意度和上次政务账单应恢复。读取旧v1至v8存档会默认标准税、满意度50，不追收或返还历史税收，下一次日结后生成政务明细。

通过标准：切换只决定下次日结；税率收入与满意度变化使用同一档位；预测和实际账单分开；暂停冻结，读档能续接且不会重复征税。

缺粮机制：按当日居民实际缺口比例扣满意度，满额缺粮15时扣10分，缺2粮扣2分。满意度变化影响后续日结税收，不追改当日已计算税收；正常供粮时低于50每日自然恢复1。低税每日+2、标准0、高税-3，最终满意度限制0至100。自然恢复仅当日无缺粮时生效。

本阶段满意度只影响税收，没有人口流失、叛乱、移民、消费档次或军队士气。粮食/材料生产不因满意度额外减速。金币保留10亿安全上限，税收入库超额部分记录为溢出。

自动任务Godot: civic test，预期CIVIC_PASS。完整构建含15项测试，debug/release共36项独立进程验收，测试库与个人存档隔离。静态参数在game/data/economy/civic_settings.tres，动态快照升级v9。

## 步骤十六 军营与基础步兵招募训练

兵源方案由用户确定：从城镇空闲劳动力征募，训练和现役期间都不能参与生产。总人口仍30，军职是其中的占用人数，不在完成训练时再次扣人口。所有数值待平衡。

1. 退出旧程序，再打开release/FrontierGuardian.exe。可读原进度；若核对初始费用则先不读档。右侧向下滚动找到建军营3×3，在普通合法陆地确认，例如(2,4)。费用木30、石10、金币30。
2. 保持施工2人、4倍速，军营约20秒完成。工地详情中招募按钮禁用；完工后可点“招募5名步兵”。若前面有其他施工，需要等待排队。
3. 保持暂停，点一次招募：扣金币50、木材5，出现民兵步兵训练批次，训练5人、现役0人；初始无其他岗位变化时空闲应从22变17，军职5。再点不能并行招募第二批到同一军营。
4. 4倍速继续约7至8秒后暂停，训练应接近50%；保存，退出重开读取，再点击军营，应恢复相同进度、5人占用和资源余额，不再次扣招募费。
5. 继续剩余约7至8秒，训练完成变现役5人，空闲仍17，不会再次扣人口。此时可招第二批；同一军营编额最多10人，满额后按钮禁用。不同军营可以分别同时训练，但都使用同一城镇兵源。
6. 经过一个完整服役日，5人军粮和军饷应各为5。首次不足一日按实际时间累计，不一定立即扣5。军需明细显示实付/应付及缺额；粮食详情会列基础口粮后余额、额外军粮和最终余粮。
7. 再保存、退出重开读取，确认现役人数、军营归属、维护零头、招募回执和军事账单恢复。尝试再安排生产或施工时，不能重复占用服役兵源。

通过标准：工地不能招募，失败不扣费/占人；招募成功仅扣一次且预留5名空闲居民；训练暂停倍速正常，完成时不再占人；军事日结和存档连续。

军粮是服役额外补给：原30人口每日基础口粮15仍保留，其中包含服役居民的基础生活粮；每名军职额外军粮1/日、军饷1/日。训练和现役都按实际服役时间累计，居民先领基础口粮、税收入库后再支付军需。粮或钱不足时不出现负数，本步只记录缺额，不形成债务、逃兵、伤亡或士气惩罚。税收仍按总人口30计算，本步不额外扣减税基。

有训练或现役部队的军营暂不可拆除，防止丢失归属；本步没有取消训练、解散、编制军团、移动或战斗。下一步再单独接入军队生命周期和编制。军营无生产工人岗位，训练由兵员自身推进，不占用全镇施工队。

自动任务Godot: army test，预期ARMY_PASS。完整构建16项测试，debug/release共40项独立进程验收。快照v10兼容旧档，旧档默认没有部队，不补发或追缴军事资源。

## 步骤十七 取消训练与解散部队

本步骤补齐此前无法取消/解散的限制。用户选择：训练按未完成比例退金币与木材，现役解散不退款。兵员立即回到空闲劳动力，已发生军需保留到日结。全部数值待平衡。

1. 打开新版release/FrontierGuardian.exe并读取原进度，点击军营。详情中的批次下拉框只列当前军营活动批次，选择训练中或现役批次，按钮分别显示取消这批训练/解散这批部队。
2. 对训练批次点取消。确认框显示具体批次编号、人数、返回劳动力、退款与保留的军需。先点保留部队：资源、人口、进度都不变，时间恢复打开窗口前的状态。
3. 再次取消并确认。5人应立即返回空闲劳动力；只有这一批5人且没有其他岗位变化时17→22；若还有其他部队则当前空闲+5。训练批次从列表消失，军营编额释放，可以重新招募新批次。
4. 核对退款：0%训练退金币50、木材5；恰好50%退金币25、木材2（向下取整）；接近完成时退得更少。退款按确认时实际进度计算，取消窗口会冻结时间。现役解散不退金币或木材。
5. 观察退役待结军需：5人已训练30战略秒，累计额外军粮和军饷各1.25；取消后不再增加，到下次日结仍各结算整数1，0.25保留。没有现役部队时，这项待结记录与相应账单仍能显示，不是新增服役开销。
6. 军营全部批次取消或解散后，可以正常拆除军营。再保存、退出重开读取，退役部队不会重新出现，兵源不会重复返还，退款不会重复发生，未结军需仍保留。

通过标准：目标批次明确，保留无副作用；取消准确退款且返还兵源，现役不退款；训练/编额/列表同步；清空后能拆军营；重开没有部队复活、重复退款或费用丢失。

招募仍每次支付新费用，新批次ID不复用。取消和解散以整批5人为单位，没有逐人裁减、部分补员或撤销按钮，执行后需手动保存。旧v10训练批次可直接读取，实付费用按已发布固定金币50/木材5补齐。

退役待结费用按已发生服务信用转入公共账户，整份日结，零头跨日并可与后续退役零头合并；不足只记录本日缺额，不转为欠款或扣兵。总人口30的基础口粮规则保持不变，返回居民不会再额外增加人口。

当前最多64活动批次、512累计批次（含退役），达到累计上限拒绝新招募，保留足够历史空间处理已有部队，不清理防重复记录。自动任务Godot: disband test，预期DISBAND_PASS。完整构建17项测试，debug/release共44项独立进程检查，战略快照升级v11。

## 步骤十八 自由人数军团编制

按用户选择：允许拆分批次，按人数自由编入。仅现役可编组，仍沿用每批5人的招募记录，不重算人口和维护。全部数值待平衡。

1. 退出旧程序，打开E:\playproject\builds\FrontierGuardian\release\FrontierGuardian.exe并读取进度。确保至少5人训练完成，暂停并展开右侧“军团管理”。
2. 新建第一团，选择一批现役5人，人数设2后点“保存本团人数”。新建第二团，同批次设3并保存，应得到2人团与3人团，未编入0。
3. 同批次总数不可超5。先将第一团降为1，再将第二团改为4可成功。数字是本团绝对总数，不是追加数量；重复保存不新增士兵。
4. 移出本团或设0只释放编制配额。撤销军团先有暂停确认，点保留无变化，确认后士兵仍现役；空闲劳动力、军营编额和资源不变。军队维护继续发生。
5. 保存、重开读取，两团人数、未编配额与现役人数一致。可在测试进度解散原部队验证：同批次在所有军团同时移除，劳动力只返还一次。

通过标准：5人能分为2和3，不能跨团超配；编组不扣费、不释放劳动力、不叠加军需；移出与撤销保留士兵，军营真实解散才返还兵源；存读档不重复分配或复活撤销军团。

当前每团20人、活动8团、历史512团。没有军团移动、战斗或逐人退役；部队解散仍整批5人。撤销与解散含义不同，窗口均说明影响。自动任务Godot: legion test，预期LEGION_PASS；完整构建18项项目测试和debug/release共48项独立进程检查通过。快照v12兼容v1至v11，SQLite仍v2。数据与边界见docs/自由人数军团编制验收.md。

## 步骤十九 军队士气

训练和现役共用城镇军队士气，起始60，范围0–100。军需按原有顺序日结：先收获、供应居民基础口粮、入库税收，再结算额外军粮和军饷。活动部队当天有整份军需到期时，两项足额则士气+2；否则每项分别按缺额比例扣分并向上取整。军粮全缺扣12，军饷全缺扣8，两项同缺时叠加。例：军粮应付5、实付2，军饷付清，士气扣 `ceil(12 × 3 / 5) = 8`。数值均为待平衡参数。

原型采用城镇共用军需账单。只有退役待结费用或活动部队当日整份应付为0时，士气保持原值；活动与退役费用同时到期时，按同一张账单的整体缺额算。士气的即时效果只体现在数值和日结变化。低士气战斗效率将在战斗系统接入时实现，第一版无逃兵。

1. 打开新版 Windows 程序。读取有现役士兵的进度，或在新局建军营并招募5人。右侧军队区显示全军士气，旧档首次读入显示60/100。
2. 以4倍速推进，供粮和发饷都足额的日结应加2点，最高100。随后让没有工人产粮的测试城镇运行到库存耗尽，军需账单应出现缺军粮、士气下降。5人军粮全缺且军饷足额时扣12，最低0，兵员数保持不变。
3. 给农场和牧场各分配3名工人，等两类建筑完工且岗位工作满一个日结周期。可生产33份粮，足以覆盖30名居民的15份基础口粮和一批5人部队的5份额外军粮。军饷也足额时应重新显示士气+2。
4. 保存并重开读取。分数和最近一次士气变化应恢复，当日日结不重复执行。若只是临时试验，可不保存。

快照v13新增 `army_morale` 与 `last_morale_before`。后者在最近一次日结无士气计算时为 `null`，有值时与同日军需账单一起验证当前分数；v1–v12迁移默认60，不追算旧账。SQLite表结构沿用v2。自动验收沿用 `Godot: army test` 和导出包军队检查，覆盖全缺、部分短缺、恢复、账单复算、旧档默认值以及 Windows 包读写。

## 步骤二十 区域地图入口

1. 退出旧程序，打开新版 Windows 游戏并暂停。在左上点“区域地图”，应见边境镇、北部林地和连接两处的道路。右侧仍可管理战略时间和查看资源。
2. 点北部林地。详情应标为“已知 · 待侦察”，说明开放需要完成军团侦察，下方进入按钮不可用。旧堡为未发现区域，地图不显示它或通往它的道路。
3. 点边境镇，再点“进入边境镇”。应返回原城镇。总览也可以通过“返回城镇”或 Esc 退出。
4. 在右侧点建住宅，但先不确认放置，再打开区域地图。返回后，预览已退出且资源余额未变。可保存并重开旧进度，验证城镇建造与军团界面可继续使用。

通过标准为城镇与区域地图的切换可重复操作、锁定区域无法进入、暂停时切换前后资源和世界数据相同。区域总览是浏览入口，侦察、战略行军和战斗将在后续接入。

区域定义存放在 `game/data/regions/frontier.tres`。地区 ID、总览坐标、初始可见性、归属、通行状态和道路相邻关系来自同一份静态配置。总览选择属于临时界面状态，战略快照继续使用 v13，现有存档可直接读取。工程战略界面测试和 Windows 包的 `world` 检查包含区域入口回归。

## 步骤二十一 北部林地侦察

1. 在军营完成步兵训练，把至少1名现役士兵编入军团。保持暂停，打开区域地图，选择北部林地和一支可用军团。
2. 点击“派遣侦察（粮食 2）”。粮食应立即减少2，林地显示“侦察中”和剩余时间。此时可保存，也可暂停检查。出发军团的成员调整、撤销以及涉及其成员的原批次解散会被暂时锁定。
3. 把速度设为4倍并继续，120战略秒约需30秒现实时间。可在中途暂停、保存、重开并读取，确认倒计时恢复。侦察耗粮只在出发时扣除，日结军需照常计入。
4. 到期后，林地显示“已侦察 · 未占领”，旧堡和新道路出现在区域地图上。军团可再次调整。保存重开后，地图应保留发现结果。

本步完成侦察、归队与发现记录。林地占领和旧堡通行留待后续，旧堡详情显示通行条件。粮食2、耗时120战略秒和最低成员数1为原型参数。快照v14记录军团ID、开始和到达时刻，v13及更早存档从未侦察状态开始。
