# 开发测试指南

本文提供每个已完成步骤的手动测试入口与明确预期。后续增加新功能时同步追加测试方法。

## 步骤一 开发环境与最小工程

### 运行与暂停

1. 用VS Code打开 E:\playproject\ffy_play\FrontierGuardian.code-workspace。
2. 按F5，选择 Frontier Guardian: Debug（如要求选择）。
3. 看到Frontier Guardian测试窗口，Running后的秒数持续增加。
4. 等待3秒后按空格：应显示Paused，秒数停止。
5. 再等待3秒：数字应保持不变。
6. 再按空格：应恢复Running，秒数继续增加。
7. 按Esc：游戏窗口关闭。

通过标准：窗口可显示，计时可推进，暂停不计时，恢复后继续计时，退出正常。若窗口显示后像卡住，先检查VS Code是否还留有断点；Shift+F5可停止调试。

### 断点和变量

打开game/scripts/main.gd，在 elapsed_seconds += delta 行左侧单击设置红色断点（当前第21行），按F5。应看到代码行变黄，左侧Locals可展开查看delta；在Members中可查看场景成员。再次单击红点取消断点，再按F5继续；Shift+F5停止。

已实际验收：断点命中_process，第21行高亮；Locals显示delta=0.03162。该数值随帧时间变化，不要求复测时相等。

### 补全连接

右下角Godot Tools状态应为Connected。如为Disconnected，按Ctrl+Shift+P，执行 Godot Tools: Start the GDScript Language Server for this workspace。端口为6008。曾出现的找不到game/godot路径问题，已通过工作区级引擎路径配置修复；已确认状态Connected。

可在脚本中尝试Ctrl+Space查看建议，不保存临时测试修改。已有的本地语言服务协议测试返回有效补全数据；补全弹窗未作为本次最终验收依据。

### 自动测试

从VS Code菜单“终端 → 运行任务”选择 Godot: smoke test。末尾应显示 SMOKE_PASS: scene, time, pause, resume，退出码为0。此测试不需要图形窗口。

## 文件用途索引

- FrontierGuardian.code-workspace：打开game工作目录并设置本机引擎与语言服务路径。
- game/project.godot：引擎工程入口、启动场景、Compatibility渲染和开发日志位置。
- game/scenes/main.tscn：占位测试界面的节点布局。
- game/scripts/main.gd：场景计时、暂停和键盘事件。
- game/tests/smoke_test.gd：自动检查运行、暂停和恢复。
- game/.vscode/settings.json：单独打开game时使用的编辑器设置。
- game/.vscode/launch.json：F5调试入口。
- game/.vscode/tasks.json：自动测试入口。
- game/.vscode/extensions.json：推荐安装的开发插件。
- .uid文件：Godot自动生成的资源标识，不手工添加注释。

严格JSON文件保持合法格式，采用本索引说明用途；GDScript文件使用中文文件头与函数或模块注释。

## 步骤二 SQLite保存与重开读取

1. 打开FrontierGuardian.code-workspace，若仍有旧游戏在运行，先按Shift+F5停止，再按F5启动新场景。
2. 看见“测试金币：100”与“数据库就绪”。
3. 点击“金币 +10”三次，应变成130，提示“尚未保存”。
4. 点击“保存”，应显示“保存成功：130金币”。
5. 按Esc关闭，再按F5重新启动，初始应恢复100。
6. 点击“读取”，应恢复130，并显示“读取成功”。
7. 再加一次变成140，但不保存，直接关闭；重开后读取仍应为130。

通过标准：保存的数据能跨进程保留，未保存的修改不会覆盖旧档。首次未保存时直接读取，应该提示“暂无存档，请先保存”。当前只有一个手动测试槽，新保存会替换这个测试槽。

开发数据库位置：E:\playproject\ffy_play\game\local_data\saves\frontier_test.db。无需安装MySQL、启动服务器或手工建表。数据库与日志不提交Git。

自动测试：运行任务 Godot: SQLite test。预期输出 SQLITE_CHILD_REOPEN_PASS 和 SQLITE_PASS，退出码0。运行任务 Godot: all tests 可顺序执行SQLite与场景回归。

断点测试请按代码内容定位 elapsed_seconds += delta，不再依赖旧行号；新增存档模块后文件行号已变化。

下一步：准备同版本导出模板，验证Windows独立程序加载SQLite与保存读取，再进入正式经营数据与战略时钟。

## 步骤三 Windows独立程序

1. 不用启动编辑器，进入 E:\playproject\builds\FrontierGuardian\release。
2. 双击FrontierGuardian.exe，应显示测试窗口、金币100和“数据库就绪”。
3. 点击“金币+10”五次，变成150，点击保存，确认保存成功。
4. 按Esc退出，再次双击同一个exe，点击读取，应恢复150。
5. 修改金币但不保存，退出重开读取，应仍为150。
6. 可选：按空格检查暂停与恢复。

通过标准：独立启动成功、SQLite没有加载错误、重开能读取已保存数值。此包与VS Code运行时的存档独立，不能要求读取到之前开发态保存的130。

移动测试包时请复制整个release文件夹，保留pck和DLL；要带走存档也需复制local_data。不要只复制exe。导出程序保存在仓库外，不上传GitHub。

下一步进入正式玩法基础：统一世界数据、战略时钟和资源面板；现有秒数仍仅为环境计时。

## 步骤四 战略时钟与资源面板

默认运行入口已更新为战略面板，旧金币加值测试仍保留在main.tscn，但不再是默认界面。

1. 打开独立release程序，或在VS Code按F5。
2. 初始应显示第1日、已暂停，人口30、粮食180、金币300、木材120、石材80。
3. 点击4倍速，再点击继续或按空格。
4. 等日期进入第2日（约30秒），立即暂停，应看到粮食165、金币320，账单显示第1日日结粮食-15、税收+20。
5. 暂停后等5秒，日期与资源应不变。
6. 点击保存战略进度，确认保存成功。关闭并重开，点击读取战略进度，应恢复刚才的日期、资源、4倍速与暂停状态。
7. 再继续到第3日，粮食应150、金币340，不应因为读档重复扣粮。

通过标准：倍速有效，午夜只结算一次，暂停不推进，战略存档能恢复后继续正确结算。超过第2日再暂停时，每多过一天应再扣15粮、加20金；请按实际日期核对。

战略存档world_prototype.db与旧金币测试档frontier_test.db分开。两个程序（VS Code、release）仍各用自己的存档位置。没有自动保存，未点击保存的进度会在关闭后丢弃。

自动测试任务：Godot: strategic test、Godot: world UI test；Godot: all tests包含全部领域和场景回归。构建流程还检查debug/release的独立进程快照保存读取。

下一步：等距城镇格网、镜头操作和格子选择，为建筑占地预览准备基础。正式地形与建筑视觉在确定样式后再制作。

## 步骤五 等距城镇格网与镜头

1. 重新打开独立release程序，或在VS Code按F5。左侧应出现菱形格网，右侧保留战略面板。
2. 鼠标移动到地图格上：出现黄色边线，下方悬停坐标跟随变化。
3. 左键点击一个格：出现绿色选择标记，下方选中坐标固定。
4. 按住鼠标中键拖动：地图移动，右侧面板不动；松开后不再拖动。
5. 在地图上滚动滚轮：地图缩放，所指地块仍对应同一坐标，已选择的格不变。
6. 按Home或点击镜头复位：地图回中，缩放回75%，选择仍保留。
7. 在地图上点右键：选中坐标变成短横线。
8. 保持战略暂停做上述操作，人口、粮食和金币应完全不变；原4倍速日结与战略存档仍可照步骤四复测。

通过标准：点哪里选哪里，移动缩放后坐标不偏，地图不会盖住管理面板，地图操作不扣资源。缩放范围50%至200%。初始图幅可能裁剪边缘，可缩小或拖动查看全图。

镜头和选择暂不保存，重开复位属于预期；已有战略档不受影响。还没有建筑，点击选格不会放置建筑。

下一步：建筑占地预览与越界、重叠合法性检查，再接入实际建造扣费。

## 步骤六 建筑占地预览

1. 重开独立release程序，保持战略暂停。右侧应出现住宅2×2、农场4×4和取消按钮。
2. 点击住宅，将鼠标移到普通空格上：应显示2×2绿色占地，文字提示位置合法。
3. 左键点击绿色位置：应提示“检查通过：仅预览，未建造、未扣材料”，资源不变，不会留下新建筑。
4. 移到中央蓝灰区域：应变红并提示占地重叠，点击后也不能放置。
5. 切换农场：占地扩大到4×4。移到地图最下方或靠边的格上，应变红并提示占地越界。
6. 预览时拖动地图或滚轮缩放：占地仍应贴合正确格网，不因缩放绕过校验。
7. 右键、取消按钮或第一次Esc取消预览；随后普通左键仍可选格。无预览时Esc退出。

通过标准：尺寸切换正确，合法绿色、重叠和越界红色，文字原因清楚；无论点击多少次都不扣费、不生成建筑。蓝灰区域只是重叠测试占用区，不是已建建筑。

自动测试运行Godot: placement test，预期PLACEMENT_PASS。此阶段绿色只表示占地合法；费用、道路、地形条件尚未接入。战略日期、资源及SQLite存档保持上一步规则。

下一步：实际确认建造、资源扣费与建筑实例存档，并防止失败或重复命令错误扣费。
