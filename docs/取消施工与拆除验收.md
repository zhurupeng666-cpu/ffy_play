# 取消施工与拆除验收

## 本步规则

用户明确选择：工地按未完工比例退木材石材，不退金币；完工建筑拆除不退款。退款依据实际建造时支付的费用，材料向下取整。例：住宅实付木20、工作量40，完成10份工作后取消退木15、金币0；农场木25、工作量80，完成1份工作后取消退木24。

详情卡新增取消施工/拆除建筑入口。确认框说明实际可退材料、上限损失、释放生产工人、未入库产量损失，以及操作后住房/粮仓容量。打开窗口冻结战略时间，取消或执行后恢复进入前的暂停/运行状态；关闭窗口取消不会改变建筑、库存、岗位或日期。

领主厅永远不可拆除。拆住宅若会导致住房不足则拒绝；目前人口固定30、基础住房30，保留此约束供后续人口增长使用。取消工地从队列移除该实例，其他工地保留进度；若取消当前工作目标，清空全局不足一份的施工信用，避免转给下一工地。

完工生产建筑拆除后工人立即释放，建筑内尚未日结的产量和零头全部丢失，之后不再产出。施工队是全镇长期岗位，不随移除单个工地自动撤人。拆粮仓减少完工容量但保留全部现有粮食，沿用超容量库存保护，新增收获仅使用剩余容量。拆除不触发额外日结。

建造材料与退款使用既有10亿数值安全上限，退款超额部分在确认框及历史回执中记录，不突破上限。执行后需手动保存；暂无撤销按钮，可在保存前通过原存档恢复先前进度。

## 身份、幂等与存档

战略快照v8新增：

- 活动建筑paid_cost：规范化的wood/stone/gold实付费用。
- retired_buildings：移除前建筑快照；不参与占地、人口、产量、容量、施工或详情列表。
- removal_commands：成功移除命令回执，包含building_id、tick、refund、overflow。

原applied_commands建造回执永久保留并可引用活动或退役实例。已移除建筑的旧建造命令只返回已处理，不复活建筑；同一移除命令重试只返回旧结果，不重复退款。不同命令再次请求已移除目标会拒绝。实例ID不复用；原址新建使用新ID，历史与活动建筑允许占地重叠。

存档校验保证：活动/退役ID唯一、唯一领主厅仍活动、所有非领主厅建筑有唯一建造回执、每座退役建筑有唯一移除回执、回执日期不超过当前时间、实付费用合法、退款+溢出与退役工地状态的可退数一致。退款历史不重复计入库存。

v1至v7兼容读取：保留经济、日期、建筑、岗位和生产信用，补空移除历史；使用building_costs.gd中的冻结历史费用表补paid_cost，不依据未来调价重算玩家旧实付成本。SQLite结构仍v2，原事务存档和三份滚动备份保持。当前支持的旧版本建筑费用表为已发布原型参数，未来调价应新增明确迁移版本。

简化新增字段示例（其余世界字段沿用完整快照）：

```json
{
  "version": 8,
  "retired_buildings": [{"id": "building_000002", "def_id": "b_house", "cell": [2,2], "level": 1, "state": "constructing", "work_done": 10, "work_required": 40, "workers": 0, "food_credit": 0, "material_credit": 0, "paid_cost": {"wood": 20, "stone": 0, "gold": 10}}],
  "removal_commands": {"remove-house": {"building_id": "building_000002", "tick": 10, "refund": {"wood": 15, "stone": 0}, "overflow": {"wood": 0, "stone": 0}}}
}
```

## 模块与事务边界

building_costs.gd规范化实付费用和冻结迁移费用；construction_service.gd在真实扣费时记录paid_cost。removal_service.gd提供只读影响预览、原子执行、退款与历史恢复校验。world_state.gd分开载入活动与退役记录，建造/移除回执整体校验后再替换世界。

确认窗口捕获稳定建筑ID与世界快照签名，执行前重做合法性和影响检查；若世界在预览后改变，拒绝执行并要求重新查看。成功时在同一逻辑步替换库存、活动记录、退役记录和回执，再同步地图、详情、生产列表与容量。

原型活动建筑上限仍256，额外退役历史上限2048；达到历史上限拒绝新移除请求，不自动删除幂等证据。未来长局应在有版本支持和测试的前提下压缩历史，当前不实现。
